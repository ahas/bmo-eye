# bmo-eye

플랫폼의 비전 유닛입니다. 세 가지 모드에 하나의 요청·응답 형태를 쓰며, 모드마다 백엔드 체인이 따로 있습니다.
유닛 자체에는 모델이 없습니다. 모든 모드는 플랫폼의 로컬 엔진이 이미 네 대의 노드에서 돌리고 있는
Qwen3.8-Flash-Next 세트를 통해 봅니다.

| Mode | CLI | What it reads |
| --- | --- | --- |
| watch | `bmo watch` | 동영상: 파일, 동영상 또는 동영상 페이지 URL(YouTube 포함). 장면, 화면 속 텍스트, 음성 |
| see | `bmo see` | 이미지: 사진, 스크린샷, 차트. 여러 장을 한 번에 |
| read | `bmo read` | 문서: 스캔본, PDF, 텍스트와 표가 담긴 페이지(OCR) |

각 모드는 체인을 순서대로 물어보고, 가장 먼저 동작하는 백엔드의 답을 돌려줍니다. 순서는 범용 팩 노드의 로컬
엔진, 그다음 세 대의 Coder 노드, 그다음 OpenRouter이며, 마지막으로 호출자가 요청했고 그 입력을 네이티브로
받을 수 있을 때 호출자 자신의 모델입니다.
동영상의 음성은 워크벤치 노드의 CPU에서, 프레임은 로컬 엔진 노드에서 읽으며, 비전 유닛은 GPU 카드를 차지하지
않습니다.
따로 지시가 없으면 플랫폼의 모든 에이전트는 이미지나 동영상을 볼 때 먼저 bmo-eye를 거칩니다.

정본은 `docs/`에 있습니다. API, 모드와 그 체인, 유닛이 거쳐 보는 엔진, 계획, 그리고 그림 요청의 레퍼런스
파이프라인 설계를 다룹니다. 아카이브 문서와 소유자에게 올리는 보고는 한국어로 쓰고, `docs/`는 영어로
유지합니다.

## 구성

| Folder | Holds |
|---|---|
| `crates/` | Rust 워크스페이스: `client`(타입과 HTTP 클라이언트)와 `server`(라우트, 저장소, 체인, `bmo-eye` 바이너리, 그리고 `openapi` 예제가 출력하는 OpenAPI 문서를 쓰는 모듈) |
| `docs/` | 문서 목록, API와 그로부터 생성되는 OpenAPI 문서, 모드와 그 체인, 엔진, 계획, 그림 레퍼런스 설계, 세 도구 엔트리 `eye/see`, `eye/read`, `eye/watch` |
| `scripts/` | 1단계 수치를 측정할 때 쓴 측정 하네스 |
| `src/` | 저장소 자체 패키지. 코드는 없고 크레이트 전체에 걸친 테스트만 담습니다 |
| `tests/` | 대역 엔진 노드를 상대로 라우트를 따라가는 테스트, 룩(look)을 이루는 미디어를 읽는 테스트, 보관된 OpenAPI 문서가 코드가 쓰는 내용과 일치하는지 확인하는 테스트 |
| `deploy/` | 배포가 재시작하고 감시하는 사용자 유닛 |

루트에는 Cargo 워크스페이스, 도구 호스트의 매니페스트 `tool.toml`과 그 엔트리가 가리키는 스키마(호스트의 요구대로
그 옆에 둡니다), 테스트베드의 `testbed.toml`, 그리고 `CLAUDE.md`가 있습니다.
