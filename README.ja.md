# bmo-eye

プラットフォームのビジョンユニットです。三つのモードに共通のリクエストとレスポンスの形を持ち、モードごとに
独自のバックエンドチェーンがあります。ユニット自身はモデルを持ちません。どのモードも、プラットフォームの
ローカルエンジンがすでに四台のノードで動かしている Qwen3.8-Flash-Next のセットを通して見ます。

| Mode | CLI | What it reads |
| --- | --- | --- |
| watch | `bmo watch` | 動画: ファイル、動画または動画ページの URL（YouTube を含む）。シーン、画面上のテキスト、音声 |
| see | `bmo see` | 画像: 写真、スクリーンショット、チャート。複数枚を一度に |
| read | `bmo read` | 文書: スキャン、PDF、テキストや表のページ（OCR） |

各モードはチェーンを順番に問い合わせ、最初に動いたバックエンドの答えを返します。順番は、汎用パックのノードの
ローカルエンジン、次に三台の Coder ノード、次に OpenRouter、最後に、呼び出し側が求めていてその入力を
ネイティブに扱える場合に限り呼び出し側自身のモデルです。
動画の音声はワークベンチノードの CPU で、フレームはローカルエンジンのノードで読み取り、ビジョンユニットは
GPU カードを占有しません。
特に指示がない限り、プラットフォーム上のすべてのエージェントは画像や動画をまず bmo-eye を通して見ます。

正本は `docs/` にあります。API、モードとそのチェーン、ユニットが通して見るエンジン、計画、そして描画リクエストの
リファレンスパイプラインの設計を扱います。アーカイブ文書とオーナー向けの報告は韓国語で書き、`docs/` は英語の
ままにします。

## モデル

リポジトリに重みは含まれていません。OpenAI 互換のチャット API を提供するエンジンを通して見ます。

| 何 | 入手先 | 用途 |
|---|---|---|
| 視覚言語モデルとそのプロジェクター | Qwen3.8-Flash-Next 系の GGUF と `mmproj` ファイルを、GPU ノード上の llama.cpp 互換エンジンで配信（このデプロイが使うファイルとノードは `docs/engines.md`） | see、read、watch のフレーム |
| ホスティングの代替経路 | OpenAI 互換のプロバイダー。このデプロイは OpenRouter の `qwen/qwen3.7-flash` を使い、キーは保存済みのシークレットに置きます | ローカルエンジンが応答しないときの全モード |
| Whisper | `faster-whisper` `large-v3`（CTranslate2 int8）。ノードの Hugging Face キャッシュに取得します | 動画の音声 |

各モデルはそれぞれのライセンスに従い、このリポジトリのコードは MIT です。

## 構成

| Folder | Holds |
|---|---|
| `crates/` | Rust ワークスペース: `client`（型と HTTP クライアント）と `server`（ルート、ストア、チェーン、`bmo-eye` バイナリ、そして `openapi` サンプルが出力する OpenAPI ドキュメントを書くモジュール） |
| `docs/` | ドキュメントの索引、API とそこから生成される OpenAPI ドキュメント、モードとそのチェーン、エンジン、計画、描画リファレンスの設計、三つのツールエントリー `eye/see`、`eye/read`、`eye/watch` |
| `scripts/` | ステージ 1 の数値を測定したときの計測ハーネス |
| `src/` | リポジトリ自身のパッケージ。コードは持たず、クレートをまたぐテストだけを持ちます |
| `tests/` | スタンドインのエンジンノードに対してルートをたどるテスト、ルック（look）を構成するメディアを読むテスト、保存済みの OpenAPI ドキュメントをコードの出力と突き合わせるテスト |
| `deploy/` | デプロイが再起動し監視するユーザーユニット |

ルートには Cargo ワークスペース、ツールホストのマニフェスト `tool.toml` とそのエントリーが指すスキーマ（ホストの
要求どおりその隣に置きます）、テストベッドの `testbed.toml`、そして `CLAUDE.md` があります。
